# 长程任务的探索恢复与停止

Agent 同时保留文件阅读进度和任务探索状态。两者不等价：读到新页面可以推进文件覆盖率，但不能证明已经完成用户的实施任务。

## 探索恢复

- 同一轮用户任务内，主 Agent 和通过 `spawn_sub_agent` 创建的子 Agent 共享探索计数。上下文压缩不会清零计数。
- 连续 12 次探索、协调或无效工具结果后提示整理结论；已有至少 4 次此类结果且超过 5 分钟时也会提示。计数按工具结果而非模型回合累积，因此并行读取也计入。
- 达到 24 次时提供一次恢复回合，暂时不向模型提供 `read_file`、`list_dir`、`todo_write`、`spawn_sub_agent`、`tool_search`；仍可使用获准的精确搜索、计算、编辑和验证工具。下一回合恢复原工具集合，之后每新增 12 次探索可再次介入。
- 更新计划、启动子任务、失败或已应用的编辑不会重置停滞状态。重复的短命令输出也不会反复获得新的探索额度；命令本身仍照常执行。
- 成功的其他工具结果会重置探索计数，但它只是运行时可观察的结果，不是任务完成的语义证明。该机制不会保证任意模型必然收敛。
- 原有重复文件/大段命令输出保护仍生效：忽略恢复指引并累计 6 批重复读取后，明确以 `CC_AGENT_REPEATED_FILE_READ` 结束未完成任务。

恢复指引要求实施任务选择最小合理修改并验证，研究/审查任务整理有依据的结论；不要求为了清零计数而修改文件，也不会因正常等待自动判定任务失败。新用户回合会创建新的探索状态。

最新计划、近期工具结果和已交付的子任务摘要以有界检查点保留，跨上下文压缩再次提供。检查点属于来源数据，不提升为系统指令，不把模型自己报告的“已完成”当成验证结果。共享探索计数不共享上下文权限：隔离子 Agent 不会因此收到父 Agent 或兄弟 Agent 的来源数据。

恢复状态通过现有 `iteration_warning` 事件显示在 CLI、REPL 和 IDE 聊天界面。

## VS Code / VSCodium 聊天 Stop

Stop 向当前存活会话发送中断，不再被可能过期的 `turnActive` 界面标记拒绝。首次点击显示中断反馈；5 秒内没有收到当前回合的终结结果，会调用现有会话终止流程。再次点击 Stop 会立即调用终止流程。Windows 使用现有 `taskkill /T /F` 清理会话进程树。

定时器绑定当前会话实例，在回合结束、进程退出、标签关闭或会话替换时清理。旧会话的后续输出不会进入新会话。停止后会话历史仍可恢复，但进行中的操作可能只完成了一部分，应检查工作区后继续。

源码变更需要被实际使用的 CLI 和 IDE 扩展加载后才会生效；已运行的旧进程不会热加载此修复。

## 回归验证

在 `packages/cli` 下运行：

```sh
npm test -- __tests__/unit/task-progress-tracker.test.js __tests__/unit/read-file-loop-guard.test.js __tests__/unit/agent-core-read-file-range.test.js __tests__/unit/sub-agent-cancellation.test.js __tests__/unit/vscode-ext-chat-slash-routing.test.js
```

包含跨多次压缩读取不同文件后实际写入修改、计划调用穿插重复读取、父子探索计数继承、隔离上下文保护，以及 Stop 状态失真和超时终止等场景。运行时测试使用可控模型响应验证调度流程，不代表真实模型任务成功率评测。
