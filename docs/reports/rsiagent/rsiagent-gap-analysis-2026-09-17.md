> 最新证据源绑定：[第十七次工程实施：签名数据库路径与 grader source digest 绑定](./rsiagent-seventeenth-batch-implementation-2026-09-18.md)。Desktop PM reader 现在要求签名 deployment 提供 database path digest，每次读取均在取得连接和执行 SQL 前核对当前绝对路径；plan、environment、路径和任务白名单形成 reader binding digest，业务 outcome source v2 再把它纳入 source digest 与签名 grader 结果。临时真实 SQLite 文件、错误路径、路径漂移、连接替换及 accessor 负例均已回归；这仍不是数据库内容快照、真实 operator deployment 或 Electron DID/RBAC E2E。<br>
> 最新执行前快照门禁：[第十八次工程实施：签名 SQLite pre-run seal 与执行门禁](./rsiagent-eighteenth-batch-implementation-2026-09-18.md)。PM execution manifest v2 现在签入 `preRunSealDigest`；Desktop 在 Actor 前通过 `DatabaseManager.backup()` 生成一致 SQLite 临时备份，绑定实际数据库路径、备份内容和字节数，并在 seal 不匹配时阻断 Actor、grader 与工具 broker。真实 SQLite 内容变化、执行前替换、路径漂移和 accessor 负例已回归，但当前机器仍没有 operator 签发该 seal，也未覆盖 workspace、执行后恢复或 Electron DID/RBAC E2E。<br>
> 最新状态迁移接线：[第十九次工程实施：执行后 SQLite seal 与状态迁移证据](./rsiagent-nineteenth-batch-implementation-2026-09-18.md)。Desktop 在受治理 round 成功返回后再次生成同一路径 SQLite seal，并将签名 manifest、execution/grader receipt、pre/post seal 与前序迁移摘要汇入可复算的 `stateTransitionDigest`；同一捕获能力的 round 已串行化，首轮核对签名初始 seal，后续轮核对上一轮 post seal，避免证据窗口交错或合法写入后仍错误比较初始状态。该包装仍未签名或耐久化，现有逐表恢复也不满足原子回滚要求，因此 workspace、异常恢复、Ledger 留存和真实 Electron DID/RBAC E2E 仍未完成。<br>
> 最新异常门禁：[第二十次工程实施：异常状态 seal 与执行 host 污染门禁](./rsiagent-twentieth-batch-implementation-2026-09-18.md)。pre-run seal 验证后若 Actor、grader、回执或 post-seal 处理失败，Desktop 会尝试捕获 failure-state seal、记录数据库身份/内容变化并永久 taint 当前 host；排队和后续 round 均在再次调用 Actor 前失败关闭，readiness 也会报告需要恢复。该失败证据仍明确为未认证、未耐久，Desktop 只读 Ledger host 没有被放宽，自动原子恢复、进程崩溃证据、workspace seal 和真实 Electron DID/RBAC E2E 仍未完成。<br>
> 最新迁移耐久接线：[第二十一次工程实施：状态迁移耐久提交能力](./rsiagent-twenty-first-batch-implementation-2026-09-18.md)。签名 Desktop deployment 现在可提供用途单一的品牌化 transition committer；它重新校验成功/失败证据、manifest、SQLite seal 与迁移摘要，并只接受同时声明认证、耐久和精确回读的绑定确认。Desktop 不取得 `commitJournal`、Ledger、artifact store 或 durability authority，成功迁移在确认前不推进内存链，确认结果不明时 taint host 且不追加可能矛盾的失败事件。当前仓库仅以合成 writer 验证协议，本机仍无 operator 签发的生产 committer、自动原子恢复、workspace seal 或真实 Electron DID/RBAC PM E2E。<br>
> 最新重启恢复接线：[第二十二次工程实施：认证迁移链头回读与重启状态重建](./rsiagent-twenty-second-batch-implementation-2026-09-18.md)。同一品牌化 transition committer 现在可选提供用途单一的认证恢复读口：固定请求按 manifest 回读耐久 Ledger 链头，重新校验空链头或完整成功/失败证据及其绑定。Desktop 在创建 execution host 前完成回读；成功链头重建下一次 SQLite seal 与前序迁移摘要，失败链头重建 taint 并在任何 Actor 调用前阻断，恢复读口缺失则 readiness 保持 blocked。该能力只裁决和重建状态链，不持有 SQLite/workspace 快照字节，也不执行文件替换或解除失败 taint；真实原子恢复仍待隔离 clone、耐久快照和 operator deployment。<br>
> 最新恢复介质接线：[第二十三次工程实施：SQLite 恢复快照耐久保留与迁移绑定](./rsiagent-twenty-third-batch-implementation-2026-09-18.md)。Desktop 现在可从同一次 `DatabaseManager.backup()` 同时取得 seal 与真实 SQLite 字节；成功 round 先耐久保留 post-run 快照，失败 round 保留可回滚的 pre-run 快照，经外部 authority 精确回读后再提交迁移。新的 v2 transition durability ack 必须绑定 snapshot ack，避免 Ledger 已提交但恢复介质缺失。真实 SQLite 字节写回后可重新打开并查询的回归已通过；当前仍未覆盖 workspace snapshot、在线主库替换、独占连接恢复控制器或真实 operator durability authority。<br>
> 最新恢复集与效果合同：[第二十四次工程实施：工作区恢复集、学习语义与等预算效果合同](./rsiagent-twenty-fourth-batch-implementation-2026-09-19.md)。Desktop 已增加 manifest 绑定的 workspace snapshot，并与 SQLite backup 合并为单一耐久 recovery set；store 可按 ack 重新回读和拆解两类介质，snapshot-bound transition recovery v2 在重启时也会先做精确 readback。旧自学习记录统一降级为 caller observation/candidate-only，技能调用收据 v2 直接绑定环境摘要且将 v1 标成环境未绑定；PM benchmark 已能冻结版本、同任务/seed/预算和全阶段成本，重算配对 bootstrap 报告。相关回归共 49 files、907 tests 已通过，但在线 clone 原子替换、operator recovery event、生产部署、真实 Electron PM E2E 和实际等预算 Pilot 仍待目标环境。<br>
> 最新 clone 恢复合同：[第二十五次工程实施：隔离 PM clone 恢复控制器合同](./rsiagent-twenty-fifth-batch-implementation-2026-09-19.md)。签名 deployment 现在可创建用途单一的品牌化恢复控制器，Desktop loader 将调用固定绑定到认证失败链头，并按顺序执行 recovery-set 回读、主库排除、独占租约、close/drain、可崩溃恢复切换证明、重开、数据库/workspace 双 seal 回读、耐久恢复事件确认和租约释放；恢复事件已成为可提交/回读的统一 `recovery` 链头，当前 host 与重启状态仅在认证结果后解除 taint。主库路径相同、切换证明不足或 seal 不一致均失败关闭并 poison controller。本轮当前工作树核心回归为 45 files、783 tests；真实平台 clone owner/recovery writer、断电演练与生产部署仍待目标环境。<br>

## 1. 结论先行

原建议的主方向可以保留：**复用已有治理与 Memory 底座，增加有界环境探索，以独立证据验证经验是否改善真实任务。** 但现有建议还不能直接充当试点实施清单，需要补齐以下五处：

1. **PM E2E 的运行配置不能直接用来证明真实 Agent、权限和恢复能力。** 测试助手声明模拟 LLM，并关闭 Actor/RBAC 守卫和数据库持久化。可以复用任务素材，必须另行建立符合试点目标的运行配置。
2. **现有部分断言不足以充当独立 grader。** 导出测试主要检查返回成功，没有回读文件内容；统计测试的部分断言仅检查返回值存在。需先补业务结果与负例验证，再评价经验增益。
3. **`ComputerUseAgent` 不能被视为开箱即用的视觉探索入口。** 当前视觉路径在截图和模型调用前主动失败关闭；隔离探针确认，注入模型服务也不会解除此限制。首个试点应优先选择受治理的结构化工具路径。
4. **Broad/Deep 方案缺少明确的逐轮反馈合同。** 原流程图把验证、经验生成放在探索之后，没有规定本轮经验如何进入下一轮规划与执行。需要补候选记忆检查点、合并、恢复和停止条件。
5. **更换名称、权限和顺序，不足以定义独立隐藏集。** 应在探索前按任务来源与族群划分训练、验证和测试，并绑定记忆来源；已有 Eval Gate 的隔离机制应直接复用。

这五项分别是运行条件、评分器、依赖就绪、方案闭环和实验设计问题，**不是五个已复现的生产故障**。本次没有发现足以认定为当前生产 P0 事故的证据。

### 5.2 G02：从返回值断言升级到业务结果验证

**建议交付。** grader 读取独立结果：按精确 ID 回查业务状态和关联关系，读取并解析实际导出文件，核对必填内容、顺序、数量及权限。执行成功、产物正确、证据完整分别记录。校验器应只读目标产物和必要状态，不与 Actor 共用可改写的期望值、评分状态或成功标记。

**验收。** 用空文件、错内容、错项目 ID、未持久化状态、错误对象和旧产物等负例证明 grader 会拒绝；合法且完整的真实产物才能通过。工具返回 `success: true` 只是输入证据之一，不能决定总任务 PASS。

**建议交付。** 把原文“复用 ComputerUseAgent”收窄为“评估复用底层动作模块，视觉循环待治理适配与接线”。首个 PM 试点用受控结构化工具即可。若后续实施 GUI 探索，先补图片输入的授权、证据快照、敏感数据处理、取消和预算合同，并在隔离桌面环境验证；临时工作目录本身不是桌面输入或网络隔离。

**验收。** 未经授权不截图、不出站；合法部署能完成一次真实视觉任务，失败/取消不会被改写成成功；记录准确模型、环境和输入证据。不能通过删除守卫或重启 legacy 路径达到“可运行”。

### 6.2 G04：让每轮验证结果真正影响下一轮

**方案缺口。** 原文第 3.1 节的图示为 Broad → Deep → 验证 → Memory，第 4 节也把“生成经验版本”放在两个探索阶段之后。它没有明确每一轮的输入 Memory、输出证据、接受条件和下一轮读取版本。已有 [ingress 完成钩子](../../../packages/cli/src/lib/evolution/agent-evolution-ingress.js#L569)可在 run 完成后排队维护及驱动 release train，但这个钩子本身不能证明探索中途已经形成反馈。

**影响与限定。** 按该文字直接实施，可能得到探索结束后的离线总结，而不是经验指导下一次探索。这里指出的是新方案缺少合同，不是认定全项目没有任何中间维护能力。

**建议交付。** 每轮显式绑定 `runId/roundId`、输入快照 digest、环境与任务分区、执行证据、独立验证回执和输出候选快照；以下是拟议流程，不是已实现入口：

```text
受治理准入 + 探索前固定的训练分区 + 候选记忆 M0
  → 课程规划 → 有界执行 → 独立检查 → 证据归档
  → 按既有权限接受候选经验，形成 M1
  → 下一轮规划/执行引用 M1（继续 Broad 或进入 Deep）
  → 达到停止条件，冻结 Mfinal
  → 重置执行环境 → 独立评测 → Review → Pilot
```

Broad 并行分支应从明确快照派生，汇总证据后处理冲突；Deep 每轮引用已接受的前一轮经验。未经验证的内容只作为待查线索。候选范围和正式发布范围保持隔离，检查点不能绕过 semantic 接受或 procedural 晋级权限。中间维护是否触发 release train 应由既有宿主合同明确控制，不能每完成一个练习就自动发布。

**验收。** 轨迹能证明第 N+1 轮实际消费第 N 轮的指定版本；无效验证不能成为已接受经验；中断后按检查点恢复，不重复不可逆动作；并行合并不覆盖冲突；总轮数、时间、调用预算和连续无增益停止条件均可审计。记录“读取了经验”与证明“经验改善效果”是两项不同验收。

### 6.3 G05：先划分数据，再开始探索

**当前事实。** 原文建议隐藏 grader，并更换名称、角色、状态和顺序；这些是有效的扰动测试手段，但没有定义独立任务来源和划分时点。现有 [Eval Gate](../../../packages/cli/src/lib/evolution/evolution-eval-gate.js#L1354)已禁止同一 group key 或完全相同 public input 跨分区，并在[产物来源验证](../../../packages/cli/src/lib/evolution/evolution-eval-gate.js#L4530)中检查 `trainingPartitionDigest` 与 `holdoutIsolated`。

**影响与限定。** 同一工作流模板只换名字，仍可能共享关键解题结构。既有精确输入检查也不能替代正确的 group key 设计。本次未发现实际训练/测试泄漏事件，发现的是新试点尚缺分组、来源和可见性规范。

**后续实施事实。** PM execution manifest v3 已能把私有 grader 的声明式进程 target、模块字节、authority、supervisor 和 deadline 固定为执行条件。grader 只在受限、可硬终止的独立进程中取得 grade request 和显式只读路径；监督回执摘要再进入签名 grader 结果。普通进程内 grader 仍保留 v2 兼容但不会被标记为隔离。该边界尚未隔离 Actor/Curriculum 自身，也没有以生产隐藏集完成泄漏验收。

**最新 Actor 隔离事实。** execution manifest v4 已可让 Actor 与 grader 同时位于不同受限子进程。Actor 只得到 run request；token 与工具请求经双向 broker 返回父进程，由既有预算和签名工具白名单裁决，监督摘要进入签名 execution receipt v2。未授权文件读取、工具越权、token 超限、模块替换和挂起进程均有真实子进程负例。Node 22 permission model 尚不能阻断网络，Curriculum/检索/模型出口也未全部纳入该边界，因此仍不能认定完整运行时隔离或隐藏集验收完成。

**建议交付。** 探索前固定数据集与 group key 合同，将同源模板及强相关变体作为组处理。训练探索只接触允许的任务与经验；验证用于选择配置；最终测试在版本冻结后使用。Actor/Curriculum 的上下文、检索、文件与工具权限均不得暴露私有评分信息，不能仅在提示词中要求“不看答案”。

目标已知练习可读取明确允许的目标描述，但必须单独标记，禁止接触私有答案和 grader。未知任务迁移须按事前定义的未见任务族群评测。同一已曝光测试结果用于改进后，下一版本应另有未曝光评测或明确降格为开发验证。

**验收。** 同族变体跨分区、错误训练 digest、测试经验进入候选、评分数据混入 Actor 可见内容时应被拒绝或标记污染；污染结果不能计入正式效果 PASS。baseline 和 candidate 都需记录初始记忆来源与冻结版本。

## 7. P2 优化与扩大试点前的条件

### 7.1 G06：旧学习模块只能贡献线索，不能自证有效

[Self-Improving Handler](../../../desktop-app-vue/src/main/ai-engine/cowork/skills/builtin/self-improving-agent/handler.js#L242)的 `handleVerifyInstinct()` 接收调用者的成功标记，并设置 `verified = true`；失败样本也会走该赋值。这里的 verified 至少不能直接解释为独立验证通过。

保留原建议：区分“已检查、检查失败、验证通过”；提取技能只产生 Candidate；正式 procedural 更新仍由 [Promotion Controller 权限](../../../packages/session-core/lib/structured-evolution-memory.js#L616)约束。迁移时保留历史来源，不给旧 verified 记录补造 grader receipt。本次未证明该字段已经绕过正式晋级门。

验收重点是迁移前后可追溯、重复导入幂等、无独立证据不得晋级，而不是删除所有旧记录或另建 Memory 权威。

### 7.2 G07：扩展环境绑定时保持协议兼容

已有 [Runtime Revalidation](../../../packages/cli/src/lib/evolution/skill-runtime-revalidation.js#L88)绑定环境、模型、工具等信息。当前 [InvocationReceipt v1 字段](../../../packages/session-core/lib/skill-invocation-receipt.js#L5)没有直接的 `environmentDigest`，但已有 run、轨迹和权限归因引用；没有直接字段不等于完全无法间接追溯环境。

应先审查间接关联是否稳定且可验证，再决定新增版本化字段还是补受信关联校验。覆盖生产者、消费者、签名/digest、持久化、历史回读和失效策略。环境变化只使受影响经验失效，不应因普通任务内容变化清空全部经验。

**最新兼容消费事实。** invocation receipt v2 已直接绑定 `environmentDigest`；session-core 现提供明确的历史读取、环境绑定归因与当前环境证据矩阵。v1 仍可按原 schema 验证和回读，但 CLI transcript outcome、Evolution Workbench metrics 与 Desktop DB outcome 不再把它视为合格归因样本；不完整 v2 同样被排除。调用方提供当前环境摘要时，stale v2 会在进入实时路由指标前失效。该回归没有改写历史回执，也没有完成生产环境复评或持久化混合历史恢复。

**最新恢复事实。** Workbench metrics snapshot 已升级为 v2 并记录兼容策略与被排除回执数。旧 snapshot v1 虽可验证，但在取得完整、认证、耐久历史并 backfill 前不能继续聚合；迁移会用全部历史核对旧 totals，再只用合格 receipt v2 重建指标，同时保留 v1 digest 用于防重放。临时真实 JSONL、SQLite 文件重开及 Ledger/artifact adapter 重建已覆盖混合历史，但这不是生产副本迁移或断电/滚动版本演练。

验收包括旧版可读但资格边界明确、环境不匹配时停止执行、复评后恢复，以及撤销/回滚后不能召回旧可执行版本。

### 7.3 G08：以真实任务收益决定是否扩大

保留原文等预算建议，并把探索、课程规划、独立验证、记忆提炼、失败重试和环境重置全部计入。固定 Actor 与辅助模型配置、工具、权限、任务集和截止条件；允许探索组改变的是事前声明的探索与记忆处理，而不是偷偷增加总预算。

一次性探索成本与复用后的边际成本分开报告。重复运行按任务/族群聚合不确定性，不把同一任务的多次采样伪装成独立任务。不设未经基线支持的“提升百分比”承诺，也不把部分分提升写成完整任务成功率提升。

达到离线门槛后仍需真实部署 Pilot、人工审核及回滚演练；不改变 `HOLD` 或自动晋级边界。该项是效果结论与扩大范围的前置条件，并非可以最后补交的文档。

1. operator 能实际签发并配置生产 deployment、authority、policy 与 audit writer；
2. 可使用真实 DID/RBAC、模型/provider、网络隔离和持久化环境；
3. 有冻结的任务集、预算、baseline/candidate 以及独立验收责任人；
4. 能安排真实 Electron E2E、身份切换/撤销、进程崩溃、断电和目标文件系统故障演练；
5. 产品、安全和运维已明确隐私审批、保留/销毁、break-glass 与回滚责任。

G03 当前工作量异常大的主要原因是统计口径已经超出“视觉模型接线”：同一状态项同时累计了浏览器动作治理、popup/navigation/download 控制、隔离工件 custody、扫描与销毁、日志脱敏、签名审计、企业 RBAC、进程监督以及部分 Remote、Plugin、LLM、Secure Storage 和 Volcengine 公共边界。排期时应至少拆成以下四个独立 Epic，公共平台项不再重复计入视觉功能工作量：

1. **G03-A 视觉观察与模型接线**：截图授权、多模态 provider、敏感信息处理、取消和预算；
2. **G03-B 页面副作用治理**：点击、输入、导航、键盘、tab、popup、多步任务及不可逆操作恢复；
3. **G03-C 下载与工件生命周期**：下载、扫描、隔离 custody、领取/导入/导出、保留与销毁；
4. **G03-D 共享生产安全底座**：身份/RBAC、签名 authority、审计、日志、进程/网络隔离和跨平台故障演练。

因此建议对外承诺“8–12 周取得可验收的结构化 PM 试点”，而不是承诺在同一周期关闭当前口径下的全部 G01–G08 或完整 G03。每两周按已取得的真实证据重估一次剩余工期；只有通过本报告定义的退出条件，状态才从“部分完成”变为“已关闭”。

### 8.2 当前能力对真实任务完成率的影响

**结论。** 当前不能声明这些工程实施已经提高真实任务完成率，但已经具备开展可信 baseline/candidate 对照实验的大部分基础。现有交付以治理、隔离、证据和恢复底座为主；其中只有少数能力可能直接改善任务求解，且尚未在目标环境取得等预算重复采样结论。

| 能力 | 对任务完成率的预期作用 | 当前可用程度 | 当前不能声明的结论 |
| ---- | ---------------------- | ------------ | ------------------ |
| G04 多轮经验反馈 | 前一轮的合格经验进入后一轮规划和执行，是最可能直接提高成功率的能力 | 轮次、checkpoint、合并、停止、恢复及合成 Broad → merge → Deep → evaluate 生命周期已具备 | 尚未在真实 PM 任务中证明后一轮因消费前一轮经验而改善 |
| G01 受治理执行条件 | 通过预算、预检、模型/Memory broker、超时和硬终止减少任务失控、中断及资源耗尽 | 本地 TEST deployment、真实 Volcengine 调用和受监督多角色执行已验证 | 尚未证明真实 Electron PM 用户链路中的成功率、成本或稳定性改善 |
| G02 独立业务 grader | 识别“调用成功但最终产物错误”，为可靠重试、修正和效果统计提供基础 | 已可独立回读 SQLite、workspace 和恢复证据，不依赖 Actor 自报成功 | 它首先提高结果真实性，不等同于提高原始求解能力；严格判定可能使表面成功率下降 |
| G07 环境绑定与失效传播 | 阻止过时经验在模型、工具或环境变化后继续被错误调用，主要避免成功率退化 | v2 环境摘要、兼容读取、指标重建和撤销传播合同已具备 | 尚未在生产环境变化、复评、撤销和回滚中证明实际保护效果 |
| G03 视觉与浏览器动作 | 扩展可处理的任务类型，使部分只能通过 GUI 完成的任务进入能力范围 | 只读视觉、单次点击/脱敏输入、有限导航、按键、开页和受治理下载已有合同 | 尚不具备可声明为可靠的自主多步视觉任务完成能力，也没有相对结构化工具的完成率增益证据 |
| G05/G06 及共享安全治理 | 防止数据泄漏、错误晋级、越权调用和不可信旧经验污染结果 | 多数合同、迁移与负例测试已经具备 | 主要贡献是安全性和结论可信度，不应计作模型任务完成率提升 |

大量已经实施的签名、RBAC、日志脱敏、下载隔离、文件持久化、tombstone、审计回执、迁移兼容和故障恢复工作，会提高安全性、可追溯性、可恢复性及对假成功的识别能力，但不会直接让模型更会解决任务。严格 grader 和失败关闭边界启用后，短期报表中的成功率甚至可能下降，因为历史上的假成功、不完整成功或越权成功会被正确拒绝。

因此当前应使用以下状态表述：

- **完成率提升能力：** 已有候选实现，核心是 G04，并由 G01/G02/G07 提供运行、验证和防退化支撑；
- **真实任务可用性：** 仅在受控测试或局部链路上部分具备，尚未形成完整生产 PM 闭环；
- **真实完成率提升结论：** 尚不具备；G08 未在目标环境执行 baseline/candidate 重复采样，也未取得签名 Eval Gate/Pilot 结论；
- **进入效果验证的条件：** 基本具备，应优先验证而不是继续无边界扩大治理范围。

#### 8.2.1 最小完成率验证

建议用 1–2 周完成第一轮结构化 PM 对照实验：

1. 从真实使用场景冻结 20–30 个任务，按任务族群分组，并保留独立未见测试集；
2. baseline 与 candidate 固定相同模型、工具、权限、预算、环境、截止条件和 reset digest；
3. baseline 不使用本轮生成的新经验，candidate 只开启 G04 候选经验反馈，避免同时改变视觉、模型或工具造成归因混淆；
4. 每个任务使用相同 seed 集至少重复 3 次，记录严格完整 PASS、部分得分、失败类型、成本、耗时和重试次数；
5. 使用 G02 grader 独立回读数据库状态和最终文件，不接受 Actor、工具返回值或页面提示自报成功；
6. 同时统计安全拒绝、超时、恢复和人工介入，不把越权成功或污染结果计入完成率；
7. 由 G08 evaluator 生成配对结果和不确定性报告，通过事前门槛后再进入真实 Pilot，否则保持 `HOLD` 并根据失败数据决定下一项工程投入。

第一轮实验只回答“受治理的经验反馈是否在等预算下提高结构化 PM 任务完成率”。它不同时证明视觉探索、跨环境泛化或生产级安全治理已经完成。测试通过后仍须按 G08 要求执行真实部署 Pilot、人工审核和回滚演练。

## 9. 建议验收标准

### 9.1 功能与证据门

| 领域       | 必须验证                                   | 不能替代它的结果                          |
| ---------- | ------------------------------------------ | ----------------------------------------- |
| 真实运行   | 生效的模型入口、身份、权限与持久化配置     | fixture DID、模拟 LLM、守卫关闭的快速测试 |
| 任务完成   | 独立产物及业务状态回读，负例被拒绝         | 仅 `success: true` 或 `toBeDefined()`     |
| 视觉能力   | 受治理图片输入和真实目标环境端到端任务     | 类存在、模型对象注入、删除保护后的演示    |
| 递归探索   | 轮次间记忆版本消费、验证、冲突与恢复证据   | 最后一次性总结、仅创建多个 Agent          |
| 隔离       | 探索前分区、来源绑定、私有评分器不可见     | 只更换任务名称或提示词禁止看答案          |
| 经验晋级   | 正式 Candidate/Eval/Review/Promotion 证据  | 调用者自报 verified 或练习一次成功        |
| 环境适用性 | 环境不匹配即失效，复评后恢复               | 只有自然语言版本说明                      |
| 效果       | 同预算、同任务协议、冻结版本和独立完整结果 | 论文数字、单次演示、只报部分得分          |
| 部署与发布 | 真实部署验收及适用的精确提交发布门         | 本地探针、旧提交 CI 或工作流文件存在      |

若后续涉及 npm 发布，仍按 [AGENTS.md](../../../AGENTS.md#L49)核验精确 release commit；CLI 的 `CLI CI` 与 `CLI Strict Sandbox` 全部已配置 OS 必须通过。本次没有发布行为。

### 9.2 实验报告合同

每份报告至少绑定：源码 SHA、runner/grader 版本与 digest、任务集与分区 digest、初始/最终 Memory、环境/权限/模型/工具指纹、预算、计划及实际运行数量、排除项和失败原因。

主指标为完整任务成功率；辅助记录部分得分、全部调用成本、完成延迟、重试、人工介入、权限违规和环境升级后的恢复成本。试点样本少时报告原始逐题结果与不确定性，不声称具备可靠的尾延迟估计。

通过、未通过、证据不足必须区分。缺样本、setup 失败、超时或 grader 不可用不得从分母悄悄删除；按预注册规则记录失败或不可比较原因。错误成功状态、越权和不可逆副作用不能用平均分增益抵消。

## 10. 不建议照搬的部分

- 不根据新闻标题做全面模型能力排名，也不将外部基准分数变成本项目验收目标。
- 不用真实用户桌面、生产数据库或未授权公网系统做自主探索。
- 不绕过多模态 ingress、Actor/RBAC、Memory 权限或人工审核来制造演示成功。
- 不将所有失败记录自动写成可执行经验，也不把高置信度启发式当作独立验证。
- 不让 Actor/Curriculum 读取私有评分数据或改写 grader；任务描述与授权信息仍应清晰可用。
- 不另建与现有 Graph、Memory、Registry、Release Train 竞争的权威状态源。
- 不以文档或合同测试完成代替真实效果、生产部署和发布验收。

## 12. 最终建议

先交付一个**受治理的结构化 PM 试点：真实运行配置 + 独立产物评分 + 探索前分区 + 逐轮候选记忆反馈**，再做冻结版本、等预算的任务对照。
