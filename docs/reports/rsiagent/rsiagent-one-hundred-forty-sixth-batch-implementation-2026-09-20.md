# 第一百四十六次工程实施：Secure Storage 原子提交与认证恢复

## 本批目标

补齐 LLM 安全配置的文件原子性与进程崩溃恢复缺口：配置、备份、恢复、密码导出和 safeStorage 迁移不能再直接覆盖目标文件；加载时只能接纳能够通过现有加密认证的完整临时文件，导入和迁移也不能在前置备份失败后继续返回成功。

## 实施结果

- 新增独立 `secure-config-atomic-file` 提交器。同步与异步写入均在目标同目录创建权限为 `0600` 的排他临时文件，完整写入并 flush 文件句柄后执行原子 rename，再同步目标目录；递归创建的目录链会逐级同步父目录。
- Windows 使用可写文件与目录句柄执行 flush，POSIX 使用可写临时文件和只读目录句柄。当前 Windows 真实临时目录已覆盖同步/异步写入、覆盖旧目标及嵌套目录创建。
- 同一进程内所有提交器共享 resolved target 锁；同步与异步调用不能并发修改同一目标。失败发生在 rename 前时会保留旧目标并清理临时文件。
- 同步与异步加载会先执行认证恢复：现有目标能解密时丢弃陈旧临时文件；目标缺失或损坏时，只有能够通过现有 `decrypt` 认证的临时文件才可原子晋升；不完整或伪造临时文件会删除并保持失败关闭。
- 配置保存、异步保存、普通备份、恢复前备份、备份恢复、密码导出及 safeStorage 迁移均已接入同一提交器。删除会同时清理正式目标和遗留临时文件。
- 备份文件名增加随机后缀，避免同一毫秒内的覆盖冲突；备份文件和新建目录使用私有权限边界。
- 密码导入和 safeStorage 迁移现在要求现有配置先完成备份，并检查最终保存结果。备份或原子提交失败时不再记录成功事件或返回成功。
- 恢复、陈旧临时文件清理和无效临时文件清理只记录三个固定事件，不包含路径、秘密内容或动态异常。

## 未完成边界

- 当前回归验证真实文件调用及故障注入，不等同于突然断电、控制器缓存丢失或文件系统故障矩阵；仍需在 Windows、macOS 与 Linux 目标文件系统执行断电验收。
- 进程内锁不能替代跨进程锁。若未来允许多个 Desktop 主进程或外部进程共同写入同一配置文件，需增加跨进程 owner/fence 与孤儿锁恢复。
- 真实 Windows Credential Manager、macOS Keychain、Linux Secret Service、系统文件选择器、损坏导入文件及用户目录 ACL E2E 尚未完成。
- tenant HMAC、秘密轮换/撤销、备份保留与受治理销毁策略仍是生产上线门槛。
