# IDE 任务记录与新会话接力

本指南对应正在开发的源码功能，需要配套更新 IDE 插件、CLI 和 Context/Memory Kernel。此前发布的 CLI `0.166.58` 不包含本功能；这里不代表已发布新版本。

## 它解决什么问题

长任务经过压缩或重新打开后，助手可能忘记已经检查的文件、失败的测试和下一步。启用本功能的 IDE 会话会自动保存任务记录，在新会话中继续时读取这些记录。

记录无需手动提醒模型撰写，不额外调用模型生成摘要。内容有长度限制，因此不能替代完整聊天或源文件。

它可以帮助减少恢复时的重复探索，但读取记录本身也会占用上下文；目前没有量化的 token 节省比例，也不能保证完全消除重复操作或循环。

## 开始一个新任务

在 VS Code 对话标签栏点击 `+`，或运行“新建对话”命令；在 JetBrains 点击 `+ New chat`，然后输入新任务。

每个标签页使用独立会话和上下文。这个入口不会自动带入旧任务，也不会停止其他正在运行的独立任务。

## 带上历史，继续当前任务

1. 在旧任务的对话中，VS Code 点击标签栏 `↗`，或从命令面板运行 `Continue in New Conversation with Task Notes`；JetBrains 点击 `Continue in new chat`。
2. 等待当前工具结束并保存任务记录。如果正在等待权限确认，请先处理确认卡。保存成功之前不会关闭旧任务或创建接力会话。
3. 新对话会预填“读取历史记录并继续未完成任务”的提示词。直接发送即可继续，也可以先修改为更具体的要求，例如“根据历史只分析失败原因，先不要修改代码”。

新对话会取得新的会话 ID，读取指定历史记录，不复制整份旧聊天，也不继承旧会话的临时权限。旧对话仍保留在标签栏，可查看历史。

“新窗口”在本版指 IDE 内的新对话标签页，不会额外启动整个 IDE。

## 在哪里查看记录

项目目录下：

```text
.chainlesschain/sessions/<session-id>/WORKLOG.md
```

可以直接在编辑器中打开。内容包括：

- 初始目标和最近补充要求。
- 已读取文件、范围、观察到的版本及有界摘录。
- 修改记录、工具结果、失败尝试与错误。
- 最近回复、模型报告的计划，以及压缩和暂停边界。

`turn-ended` 只表示一轮结束，不能当作任务已经完成；启动了但没有结果的工具会标为结果尚不明确。

记录在用户输入、工具执行前后、最终回复、压缩前后、正常退出等节点更新。进程被强制终止时，最后一次已经保存的检查点仍可恢复，未完成的操作需要核实。

Markdown 最大 32 KiB，较旧的明细会被裁剪，并保留裁剪计数。读取过的文件仍可能变化，接力会话需要在修改前重新核实相关片段。

## 与统一记忆的关系

任务检查点由 Context/Memory Kernel 管理，保存在现有会话日志中；Markdown 是便于查看和交接的投影。Markdown 缺失时可以从检查点重建。

请通过对话补充目标或纠正结论，不要依赖手工修改自动生成的 Markdown 来改变会话状态；交接时会与权威检查点核对。任务记录不会自动加入长期记忆。

## 常见情况

| 情况                | 处理方式                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------- |
| 提示需要更新 CLI    | 更新配套组件后先发送一条消息，等待会话初始化，再尝试交接。旧 CLI 不会被当作支持此功能。  |
| 等待保存超过一分钟  | 旧对话保留。检查是否有运行中的工具或待处理确认卡，处理后重试。                           |
| 提示无法保存记录    | 检查项目目录权限、磁盘空间和 Context/Memory 模式。未成功保存时不会迁移。                 |
| 历史加载失败        | 新会话不会开始执行任务。保留旧会话，检查工作区是否相同、会话日志是否仍存在，修复后重试。 |
| 手动删掉了 Markdown | 只要原会话检查点仍存在，交接时可重新生成。删除 Markdown 不等于删除原会话历史。           |
| 文件已被他人修改    | 根据最新文件核对历史结论，允许针对性重读；记录中的旧版本不是当前内容。                   |

## 当前范围

本版支持显式点击接力，没有启用按 token 阈值自动迁移，也不会根据普通消息自行判断并切换任务。新任务请主动新建对话。这样可以控制交接次数，避免不断创建新会话延续同一循环。

插件默认启用任务记录，遵循 Context/Memory 的既有模式；shadow 模式只观察、不写任务检查点。常见凭据会在记录中被遮盖，但记录仍可能包含项目代码与错误信息，分享前应检查。仓库已忽略该运行目录；其他项目可自行将 `.chainlesschain/sessions/` 加入 `.gitignore`。
