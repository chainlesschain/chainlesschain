本批修改 [subagent-inheritance.js](../../packages/cli/src/lib/subagent-inheritance.js)。原先指定服务器列表会丢弃没有服务器名的 `tool_search`，而允许继承所有服务器时会共享父任务的搜索 registry。新实现为已继承的延迟工具建立子目录，只有父任务已有且允许继承的搜索入口才会一并传入。撤销检查继续读取源 registry 的 entry 身份，避免复制后把父任务已撤销的 schema 永久保留为有效状态。

[运行回归](../../packages/cli/__tests__/integration/subagent-mcp-discovery.test.js)实际经过 `executeTool → spawn_sub_agent → SubAgentContext → agentLoop`，记录子任务各轮收到的 schema，并核对搜索结果、MCP 调用次数和原宿主 dispatch admission。模型和 MCP client 为注入夹具，未连接外部模型或真实服务器。6 项测试分别覆盖 compact / stubs 搜索调用、搜索后父目录撤销、父能力拒绝搜索、host 拒绝工具及默认 fresh 不继承。

负例在 Vitest transform 中替换回 `1a73bd7502` 的原始继承模块，Git blob `9cd41313b14778db3049b0c01b6fc0af1423e779` 一致；不修改磁盘上的生产文件。原始成功与失败报告、旧源码、transform 配置以及 7 个源码 / 测试 / 配置文件的 SHA-256、Git blob 见[证据回读](./cli/evidence/subagent-mcp-discovery-2026-10-29/review.json)。完整 192 项验证使用 Windows、Node 22.22.2、标准 CLI Vitest 配置与单 worker；格式、命令清单、进程启动清单及 diff 检查通过。

迟到连接不能简单把父任务数组变成共享可写数组：当前运行的执行策略会冻结工具能力上限，headless 组装、继承筛选、SubAgentContext 和 agentLoop 又各自捕获目录。后续需要明确区分可信宿主更新与调用方修改启动参数，并验证取消、撤销及 schema 替换。本批不据静态检查认定该场景已修复，也不将 192 项本地回归计入 36+9 真实任务；累计合格产物仍为 **34/45**。
