**磁盘语义变化：** 有效 bundle 存在时，它是当前查询验证的派生表示。原独立索引文件作为兼容副本，不再每次热查询逐个打开、验证或修复；bundle 重建时重新验证这些副本。该变化不把独立文件损坏解释为 authority 损坏，也不能宣称每个兼容副本每次查询都已检查。原有逐文件修复测试显式选择 `individual`，默认布局另保留未选中 frame 损坏、发布失败和取消回归。

bundle 名称使用独立 domain 对 manifest 摘要再取哈希，形状仍为旧 collector 认识的 `query-00-<hash>.json`；新 collector 仅保留当前 generation，发布后收集旧 generation。临时文件复用旧版认识的 rebuild 名称。写入临时文件、fsync、目录 / 文件身份复查、rename 后目录同步；清理只删除仍符合创建时身份的临时路径。路径冲突时拒绝使用 bundle。

## 诊断及规范化实验

第一次 bundle 短测为三档冷 / 热各 11 次。100K 冷 / 热 p95 为 **1764.628 / 404.778ms**，未达标。一次独立冷查询 CPU profile 的 wall time 为 **1470.619ms**；调用区间中，读取 / 编译 bundle 为 502.740ms，选中 shard snapshot 为 874.947ms。采样归因显示选中分片规范化约 727ms，任意 canonical 栈约 545ms，重复索引哈希约 52ms。归因会重叠，不能相加；这一次诊断不是 p95 或发行门禁。

据此去掉内部已验证 frame 的重复哈希，保留 codec 的完整磁盘 frame 哈希，并复用借用缓冲。Astra 对 canonical 分配做独立实验：直接序列化更慢；最初 null-prototype 原型在微基准更快，但进一步检查发现继承 `toJSON` 和数组行为边界，因此未直接采用该版本。

最终内部树保留原数组 `.map` 行为，先用无原型对象安全填充属性，再恢复普通对象原型。公开 `canonicalize` 保留原行为；最终文件经 Prettier 格式化，不将函数源码文本完全相同作为交付声明。兼容原型七轮轮换微基准中，JSON / digest / clone 中位数分别为 **154.160 → 131.464ms、198.845 → 183.251ms、198.231 → 175.675ms**。所有轮次均改善，但这是同进程预热的 3K 记录、3K 事件及完整状态实验，不解释为最终查询收益。

复查发现内容错误会在正常尾部身份核对前抛出，可能把读取期间替换路径的情况交给重建。codec 现在在错误路径也核对 fd 与当前路径身份；port 在成功 / 失败两条路径均核对目录，然后才决定返回或重建。这样无匹配结果也不能绕过目录复查。该修复不宣称所有文件系统调用之间具备原子防替换保证。

CLI 110 项回归后仅对 canonical 源文件进行了 Prettier 格式化；[格式对照](./cli/evidence/memory-query-bundle-2026-10-29/raw/canonical-format-parity.json)确认只有该格式变换，随后完整重跑子包测试和 e7 对照。最终查询 / Stop 回执绑定最终源码字节；不同阶段的测试数量不跨批累加为一个全库通过数。
