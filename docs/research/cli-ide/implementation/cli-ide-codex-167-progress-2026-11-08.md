**实现与复核**

四份官方 schema 按生成器原始字节保存，并记录 npm integrity 与 SHA-256；契约测试独立覆盖 `.160/.164/.167`，每个版本使用独立校验器缓存。生产路径仍为 `codex exec --json`，App Server 默认关闭，`.167` 不在实验允许列表中。

Astra 独立复核找出了断流验证的假阳性：原探针只要求外层“受理后失败”，总超时也能满足。现已让客户端锁存首个传输失败并通知所有未结束的执行；适配器保留明确终态，对未确认提交或已受理任务禁止重复 fallback。探针等待实际受理回执后再杀进程，必须观察到 `TRANSPORT_CLOSED` 原因，不能用 `TIMEOUT` 代替。

本机还复现了 Windows 子进程已发出 `exit`、但 stdout/stderr 未关闭的情形。清理现先确认真实进程退出，再等待有限时间排空管道，必要时关闭本地流并标记 `stdioForcedClosed`，最终仍等待 `close`。这不是通过销毁管道推断进程退出。若最终通知滞留到进程退出后，本实现会保守报告失败。

历史探针原先在停止客户端失败后跳过关闭 HTTP 服务，导致失败报告已经写出而探针仍驻留。现在各客户端和 provider 独立、有界清理，保留原始错误，同时写出 `cleanupErrors`。新增测试覆盖并发执行、受理回执时序、已有终态保持、首次错误锁存、管道清理，以及客户端清理失败时真实 HTTP 服务仍关闭。
