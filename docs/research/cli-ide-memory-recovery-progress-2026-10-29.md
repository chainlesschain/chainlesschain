## recall 一致性与取消

原 Kernel 在 `query()` 返回后单独读取 revision；并发 writer 可以在这两个时点之间删除或替换记录，导致旧结果被贴上新的 revision。新实现依赖 MemoryPort 的单调 revision 契约，以前后读取相等为乐观稳定性条件。空结果也必须通过；任何变化停止本次 provider context，调用者可以显式重新读取当前 authority。

这是查询期间的稳定性守卫，不是跨调用单调监控，也不持锁覆盖最终核对到模型发送之间的窗口。通用 MemoryPort 的 I/O 取消仍由宿主协作实现，不能把这项版本检查解释为任意异步端口都可抢占。

语义候选接口的序列化请求不变，signal 放在第二个宿主控制参数中。microtask 中实际调用候选源之前，取消监听与源 Promise 的 rejection handler 已安装，覆盖候选源同步 abort 后拒绝、Stop 后迟到成功和迟到失败。等待取消不证明不合作宿主的底层工作已经终止。相关接口及发行边界已写入 [Kernel README](../../packages/context-memory-kernel/README.md)。

## 压缩与恢复的实际覆盖

新集成测试先注入一条可用记录、一个其他 agent 的记录及一个其他 provider sink 的记录。第一次请求后真实提交 supersede 或 delete，随后两个本地 read_file 工具轮次触发 canonical 压缩。第二次请求及 ContextPlan 的 revision 均与当前 Memory 一致，旧记录和越权记录不可见。保存的权威 JSONL 消息保留工具轮次，但不包含注入的 Memory 文本标记。

接着更新 Memory，再次调用同一入口的 resume，验证新的记录与 revision，以及已保存工具轮次。压缩触发条件被测试强制，摘要与模型响应为注入夹具；它不验证自然阈值、真实摘要模型质量、独立进程恢复或所有磁盘副本的物理擦除。本批也没有改变旧 REPL 的启动注入或清理历史普通文本，不能声称所有 Memory 刷新与恢复已完成。

## Windows CI 回读与身份兼容

准确 `673c2520a84f884dc4d072e222078f31b3090718` 的 [Memory Query CI](https://github.com/chainlesschain/chainlesschain/actions/runs/40806303385) 为 **Linux / macOS 成功，Windows 失败**。Windows 在 bundle 的 path / fd 身份比较中失败，原始完整日志保留。本机 Node 22.22 通过的结果没有替代该失败。

仓库既有 `secure-file-identity.js` 已处理 Windows / libuv 1.49—1.50 的 path device 投影差异。bundle 复用其受限桥接，并将文件身份读取及时间比较改为 BigInt / 纳秒，避免大 inode 的 Number 精度问题。真实 inode 或父目录设备不一致仍拒绝；现代运行时不扩大零设备例外。新增 CI 诊断保留 Number / BigInt 两套原始字段、uv / OS 版本和独立父目录信息，在测试失败时也上传。

本机旧 Node 位于 OS 19045，并未原生表现出设备投影差异；确定性注入证明大 inode 与受限投影下旧实现的四项读写用例失败，修复后通过。**历史 CI 主机的实际字段差异仍需新诊断确认**，不能把本机注入等同于已经回读该主机的原始 stat。

旧 673 源码的两个 Unix 报告完整回读，每系统三档 × 五场景 × 11 次，共 165 次结果核验。100K 热 / 冷 p95：Linux **146.344 / 836.310ms**，macOS **483.947 / 617.113ms**。均为短采样；macOS 热查询超标，Windows 未完成测量，也不是本批新源码的重跑，不能宣称三系统 SLO 达标。
