# 组织目标建议与多级审批

更新：2026-10-07。第十二批接入共享目标的风险建议、实际执行意图、多级审批及原生任务写入。复用现有组织提议、审批、Task action、ActionRun 和目标预算；本批未发布。

## 使用方式与权限

在“组织任务与审批”的目标卡片中点击“确认允许目标任务建议”，由具有 `goal.update` 的成员原生确认 `allowedActionTypes`。默认没有允许的任务操作；本批界面启用 `task.create` 与 `task.update-description`。随后执行一次手动检查或等待已授权周期检查，风险记录会在同一事务生成建议。

建议仅针对逾期和未完成直接依赖的真实规则信号。创建风险处理任务或修改说明不会自动执行任务，也不会自动消除风险或通过目标验收。

| 身份与操作         | 所需权限                                                                         |
| ------------------ | -------------------------------------------------------------------------------- |
| 阅读目标与风险历史 | `goal.read`、`risk.read`；不要求任务权限                                         |
| 阅读建议与审批关联 | `goal.read`、`risk.read`、`task.read`                                            |
| 准备与提交建议     | 上述权限，加独立 `goal.propose` 与对应 `task.create` / `task.update-description` |
| 审批               | 指定审批成员的 `task.approve`、`task.read`、`goal.read`、`risk.read`             |
| 最终执行           | 固定请求者本人，当前目标/任务/风险权限和全部审批仍有效                           |

目标创建者只保留归因，实际准备建议的当前成员成为固定 executor。其他成员看到已占用建议的执行者、状态和审批元数据，不得到其准备正文或预览；执行不能换人。授权配置和迁移设置新增明确 `goal.propose`，目标权限不隐含任务权限。

输入拟保存说明，创建任务时选择任务类型，点击“核对当前来源并预览”。预览不会写入 Task，也不会占用长期审批预算。选择适用审批计划并提交，随后在现有提议区由其他成员逐级原生核对。全部批准后，仍由请求者点击“本人确认执行”。原生审批与最终确认展示目标说明、版本、意图、风险来源和修改内容。

## 固定证据、预算与恢复

共享建议按目标/control generation、操作类型、来源任务及语义风险信号去重，重复检查不会生成同一信号的新建议。每次检查最多新增100条，每个目标最多500条，容量不足保留全部风险证据并返回省略计数。新的检查更新建议来源关联，不改已经准备的意图来源。

一个共享建议只能占用一个执行意图。prepare 固定实际 actor、目标 revision/control generation、定义摘要、完整组织 authority、risk review/摘要、Task/Project 版本、请求 ID 与原始预览。intent 与组织审批提议在同一个 SQLite 事务绑定，不能换成员、建议、目标、工作流或幂等键绕过原意图。

审批 companion 在既有绑定中保存 `goalIntent`，沿用 ActionRun 的六字段引用格式。所有指定审批人都需要目标和风险读取授权。提交、审批、准入、原生确认后及写入前后核验目标状态、版本、到期、政策、成员、完整来源和意图绑定；暂停、修订、来源或授权变化使旧意图失效。列表把这些旧建议标为历史；同一原请求仍可在当前读取权限下核对既有终态。

通用组织提交/执行入口也必须验证目标上下文；存在 `goalIntent` 但没有可信 workflow 时拒绝。复用目标意图 nonce 并剥离上下文不能绕过。独立的非目标组织任务提议保持既有授权和审批流程。

prepare 只检查目标余额。真正原生 action admission 才预留一次操作预算，成功后结算；取消/确定拒绝释放，未知结果保留保守占用。手动检查、周期检查和任务操作按整个目标跨成员共用预算；目标修订、换 executor 或新请求不能重置累计量。

Task 写入、审批消费、ActionRun 回执、目标意图状态和成功用量在同一个事务完成。任一步失败都会回滚 Task 和审批消费；未决 admission 保留，不能自动换请求重写。回复丢失时沿用原请求读回，成功不会重复确认或计费。真实进程在原生确认未完成时退出后，重启把 running 用量保守恢复为 unknown，原 nonce 仍 unresolved，不再次确认。
