# 组织目标独立验收

更新：2026-10-07。第十三批完成共享验收计划、成员原生人工确认、最新事实检查及有证据的目标完成。源码和本地验证保存到main，本批未发布。

## 使用与授权

项目详情的“组织任务与审批”中，每个目标提供独立验收区。成员先选择条件并原生确认保存计划，再核对业务结果、记录人工验收，最后显式检查或原生确认完成目标。任务创建、描述修改、风险巡检或审批成功不会自动完成目标。

| 操作                   | 明确权限                                                                         |
| ---------------------- | -------------------------------------------------------------------------------- |
| 读取共享验收计划与报告 | `goal.read`、`risk.read`、`task.read`                                            |
| 原生保存验收计划       | 核心要求 `goal.read`、`goal.accept`、`goal.update`；当前界面另需验收区的读取权限 |
| 记录本人原生人工验收   | 核心要求 `goal.read`、`goal.accept`；当前界面另需验收区的读取权限                |
| 检查最新验收事实       | 读取权限，加 `goal.accept` 与 `risk.evaluate`                                    |
| 原生确认并完成目标     | 检查权限，加 `goal.update`                                                       |

创建者仅保留归因。不同当前授权成员可以配置计划、确认人工条件、最终检查和完成；报告与人工确认保留各自实际DID。目标/风险读取者没有任务权限时仍可读取原有目标与风险历史，验收区不加载业务事实。

## 四类条件

| 条件                   | 真实判定                                                            |
| ---------------------- | ------------------------------------------------------------------- |
| 项目非空且全部任务完成 | 重新读取规范任务，项目至少有一项任务，全部状态为completed           |
| 选定风险信号消除       | 从最新规范来源重新运行逾期/未完成直接依赖规则；不足来源不能满足条件 |
| 跨成员目标动作均已处理 | 检查整个目标、所有执行成员和历史版本的意图、ActionRun及审批证据     |
| 成员人工验收           | 当前目标/计划和实际来源有效的原生确认；取消不满足条件               |

业务断言与人工条件有明确ID和类型映射，最多50项；不解释模型文字、进度数值或自定义SQL为验收。配置保存会更新目标revision/control generation，使旧周期同意及动作版本失效。后续合法任务推进允许继续使用同一计划；政策、成员、映射/schema、目标定义或版本变化须重新配置。界面明确提示历史计划不可继续使用。

人工确认绑定当前完整authority及事实来源。任务在确认后推进时，旧人工确认不适用于新的业务结果，需要成员重新核对；确认和验收配置的actual actor不等于creator。取消人工确认写入不可变cancelled回执，同nonce不能随后改为accepted。

## 动作终态与未知结果

draft/prepared/submitted、待批准和未执行批准不自动算动作完成。已有原生succeeded/denied/cancelled ActionRun可解除对应动作；被拒绝的审批必须核验不可变响应companion，取消必须有新增不可变取消凭据。到期本身不代替处理：只有请求者明确取消并留下可信凭据，才能把已经到期且没有消费的审批视为已处理。

任何跨成员、历史版本的native running/unknown动作，以及未知用量，都会硬阻止目标完成，即使没有勾选“动作均已处理”。不能换成员、新请求、新目标版本或删去该条件掩盖未知写入。

动作来源读取最多500个目标意图；计划/确认/事实/报告有512KiB记录边界和显式数量限制。读取不足、完整性损坏或库错误拒绝，不降级为空列表或伪造满足。

## 确认、事务与恢复

最终原生确认显示真实目标、版本、条件判断、共享预算、事实及请求摘要。预览只读，不持久写风险或扣预算。用户确认后重新核对完整authority、当前规范任务、人工确认、跨成员动作、审批证明和用量；来源、权限、身份generation、窗口/frame/导航或时间敏感判断变化拒绝旧确认。正常等待本身不会因asOf改变而失效。

检查与完成都生成新的原生风险来源、独立source/fence/report并计入全目标预算。未满足条件也保留真实报告、结算一次检查用量；没有假完成。report、source、fence、用量、完成CAS及monitor更新在同一个SQLite事务完成，任一步失败全部回滚。普通revise仍拒绝直接写done、completion或验收条件。

完成使用纯GoalRecord完成合同和专用组织CAS，保留control generation语义，要求当前goal.accept/goal.update及真实已落盘报告。完成后monitor持久标为GOAL_COMPLETED并关闭后续周期，保留pending slot及active occurrence；不宣称在途检查已同步杀死。

configure、人工确认、检查及完成都有actor/goal/kind/requestId幂等身份和输入摘要。回复丢失沿原请求读回，不重复原生确认、风险检查、用量或目标版本；终态共享历史复核来源、原始判断、审批/ActionRun、人工记录及预算，不依赖新的执行资格。历史报告描述当次事实，不把旧met报告当作本次完成许可。

界面在调用前保留完整原请求，当前会话父刷新和done状态仍可核对；未决请求期间禁止提交另一种验收操作。项目/组织/身份/权限变化清理事实与恢复线索，丢弃迟到响应。验收条件成立只证明已选定的本地条件及成员声明，不代表外部客户或生产租户验收。
