# 组织目标共享记忆

更新：2026-10-07。第十四批复用现有 `ContextMemoryKernel` 与 `NativeSqliteMemoryPort`，接入组织目标共享记忆。创建者只保留归因；当前成员权限决定读写和恢复资格。

## 使用与授权

项目详情打开“组织任务与审批”。所有者在明确成员政策中配置以下权限，原生重新确认后，目标下显示“组织目标共享记忆”。旧 `goal.read/update` 不隐含记忆权限。

| 权限                 | 内容                                                                 | 同时要求    |
| -------------------- | -------------------------------------------------------------------- | ----------- |
| `goal.memory.read`   | 共享记忆分页、当前成员无正文操作记录                                 | `goal.read` |
| `goal.memory.write`  | 保存、修正、撤销目标使用权，恢复自己的保存/修正/撤权，放弃未完成保存 | `goal.read` |
| `goal.memory.delete` | 删除共享记忆，恢复自己的删除                                         | `goal.read` |

界面读取正文另外需要 `goal.memory.read`。核心删除及其恢复不要求记忆读写权限，也不要求 `goal.update`。所有操作仍需当前 active 成员、有效政策和明确组织项目绑定。其他授权成员可读取、修正、撤销或删除共享记忆；创建者 DID 不作为 ACL 或执行主体。

保存分类为成员明确事实、Agent 推断、执行备注，可指定到期时间。每次新的保存、修正、撤权、删除和放弃都需原生确认。确认展示实际成员、组织/项目/目标/版本、源记忆版本、内容分类、正文、到期和请求摘要；默认取消。恢复原请求不重新确认或创建另一条记忆。事实、推断和备注均不替代独立业务验收。

## 存储与一致性

Kernel 拥有正文、版本和生命周期。组织目标只保存 `{kind:"context-memory-kernel",id,version}` 引用，独立授权链接决定该版本能否输出。共享 namespace 固定目标 store、组织、绑定版本、项目和目标，不包含创建者或当前成员；个人目标与其他组织/项目/目标不能互读。

| 组织目标表                                       | 内容                                                        |
| ------------------------------------------------ | ----------------------------------------------------------- |
| `cc_organization_project_goal_memory_authority`  | 整个共享目标的持久记忆 epoch                                |
| `cc_organization_project_goal_memory_links`      | 目标与具体 Kernel 版本的授权状态和操作归因                  |
| `cc_organization_project_goal_memory_operations` | 目标/实际成员/请求 ID、输入摘要、准入授权、状态及无正文结果 |

目标与 Kernel 表在首次组织 schema fence 前初始化。正文不写入目标记录、组织操作账本或 Kernel 生命周期事件。单正文限 8192 UTF-8 字节，链接和操作数量有上限，分页限 50；损坏或超量元数据拒绝读取。

保存/修正的链接、原操作结果、目标引用 CAS 和 epoch 在同一 SQLite 事务落盘。Kernel 异步写入与目标事务分开；前者成功而后者失败时保留原请求，正文未获目标 grant，不可因裸引用读取。修正先由 Kernel 保留旧版本 supersede 证据，再原子切换目标 grant 与引用。未知结果不自动执行或换 nonce。

撤权和删除先拒绝本目标的正文使用；删除通过 Kernel 删除与 reconciliation 回执完成清理。部分删除保留阻断状态，原成员可用删除权限恢复；不能以超时推定已清理。已完成目标保留历史引用，隐私清理仍通过独立 grant 阻断正文，不伪造新的完成证明。

## 授权、输出与恢复

准备、原生确认之后、Kernel authorize 回调、异步返回、目标事务和最终 IPC 返回都重验实际成员与完整组织 authority。同 DID 重新登录、数据库/窗口/frame 替换、导航 ABA、成员/政策/绑定/schema/来源变化及授权到期使在途调用失败。

正文输出绑定实际成员、组织 scope、目标 revision/control generation、持久记忆 epoch、完整当前 authority、权限截止时间和精确版本引用。宿主返回前重新核对输出 token；旧页、裸引用、撤销/修正/删除/到期后的版本不能继续使用。

操作账本按实际成员分区，同名 nonce 在不同成员间独立；其他成员不能恢复或放弃别人的未决保存。恢复重新要求当前完整权限，并核对原请求、scope、目标版本、Kernel 原始内容摘要与生命周期/删除证据。准入 authority 保留为归因，不作为永久授权。重新授权可恢复合法隐私清理，旧输出 token 仍失效。

若 Kernel 尚未保存正文，恢复返回需要原始输入，不从账本补造内容；用户可原生确认放弃后重新提交。Kernel 已提交而回复丢失时，同 nonce 核对已存版本，不重复写入。原生取消不创建操作账本或记忆；身份或权限失效不会被记录成普通取消。

## 桌面与界面

新增八个固定 IPC：`organization-project:goal-memory-list/create/correct/revoke/delete/operations/recover/discard`，及无正文事件 `organization-project:goal-memory-invalidated`。preload 提供明确方法与可退订的事件订阅，无通配记忆权限。

组织目标面板保留无正文的原请求恢复线索，父工作区或目标刷新卸载子面板后仍可核对同一 nonce。项目、组织、成员、登录代次或权限变化清除内容、草稿和恢复线索，迟到结果丢弃。实际成员 DID 与界面认证 key 分别传递，带登录代次的 key 不充当业务身份。

刷新和分页替换旧正文。失效事件、父工作区忙碌、记忆到期和授权截止都会清除正文及修正草稿；显示期间最多每 30 秒重新检查授权。删除/撤权等待原生确认时已经清除显示内容。界面只保存待核对 nonce，不在父层持久保存记忆正文。
