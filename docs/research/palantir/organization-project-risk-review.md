# 组织项目风险检查、人工核对与操作血缘

更新：2026-10-07。第九批完成组织风险共享服务、桌面入口与本地验证。组织目标、附属及看板操作仍待适配；本批未发布。

## 使用方式

在项目详情打开“组织任务与审批”。组织所有者先在成员授权中明确勾选风险权限，并重新原生确认政策。已有任务授权不会自动获得风险权限。

| 权限            | 可用操作                               | 额外要求                         |
| --------------- | -------------------------------------- | -------------------------------- |
| `risk.read`     | 读取检查、共享历史、关联操作和人工核对 | 当前成员、政策和显式项目绑定有效 |
| `risk.evaluate` | 检查当前风险                           | 同时持有 `risk.read`             |
| `risk.feedback` | 原生确认后保存人工判断                 | 同时持有 `risk.read`             |

仅有风险权限的成员也可打开风险区域；不会加载任务描述、任务提议或审批计划。具有任务权限而没有 `risk.read` 的成员不显示风险区域。评估者 DID 是归因信息，当前合法成员可跨评估者读取共享历史。

“检查当前风险”按实际规范 Project/Task 数据生成检查记录。规则仅识别未完成任务逾期和未完成的直接依赖，不预测交付结果。缺列、超出任务限额或损坏依赖返回数据不足；数据库读取失败返回错误，不以空数组伪装成功。历史结果明确显示检查者和来源时间；模型 usage 和费用未知。

选择检查后，可将其明确关联到任务创建或描述修改提议。预览产生的不可变请求包含检查 ID 和完整内容摘要，提交后跨身份多级审批，最终仍由请求者原生确认执行。描述修改不会消除规则信号；任务创建只保存 pending，不执行模型、部署或外部动作。不关联检查的既有组织提议保持原合同。

所有指定风险提议审批人都必须有 `risk.read`。审批原生对话框显示检查、来源时间、任务信号和摘要；执行原生对话框再次显示绑定的检查与摘要。提交、审批、准入和最终事务都重验来源新鲜度；旧检查不能代替完整 Task/Project `expectedVersion`。来源改变后，旧提议不可继续审批或执行，请求者仍可查看和取消，再重新检查并准备提议。

人工核对独立追加保存。确认信号和仍需核对记录所选任务的原规则原因；排除信号保存空原因列表，保留原始规则事实。说明最多 4096 UTF-8 字节。取消原生确认不写入；回复丢失后只读取记录核对，不自动重复写入，同一身份/项目/检查的核对表单暂时锁定。

## 服务与存储合同

`OrganizationProjectRiskReviewService` 使用实际原生 SQLite 和组织权威，与个人风险表、权限和入口分开。构造不补写任务样例，也不迁移真实规范表的列。

| 独立表                                      | 内容                                                           |
| ------------------------------------------- | -------------------------------------------------------------- |
| `cc_organization_project_risk_reviews`      | 评估者、项目、时间、权限快照、选定字段来源、规则结果及内容摘要 |
| `cc_organization_project_risk_action_links` | 检查与实际 ActionRun、准入摘要的关联                           |
| `cc_organization_project_risk_feedback`     | 人工判断、归因和内容摘要                                       |

三表的 UPDATE/DELETE 由不可变触发器拒绝。当前没有自动清理/保留期限入口；不可变是本地合同，不是独立签名或外部不可改写证明。

检查结果为 `{review,sourceSnapshot,evaluation,authority}`，四部分共同生成摘要。来源保持纯规则所需的六个字段：`sourceSchema/readStatus/asOf/scope/project/tasks`。沿用 `desktop.project-tasks/v1` 和现有风险规则；组织 scope 来源于显式绑定。任务最多 1000 条，完整记录最多 2 MiB。

历史读取要求当前授权及原组织映射、来源归属与任务位置有效，验证摘要并重算原规则。历史不要求旧 policy epoch 仍为当前；用于动作则要求完整 mapping/policy/org/project/schema 版本及规则选定字段仍匹配。角色、撤权或数据改动后恢复原内容，不恢复旧动作资格。其他组织、移项、删除或 workspace 归属不通过历史访问检查。

风险源、组织审批消费证明及实际 ActionRun 通过共享的纯回执验证器关联；不为风险读取创建任务执行器，也不引入 `task.read` 要求。关联准入和本地动作执行保持事务边界；成功、取消、拒绝及未决回执可查。普通风险回执/人工核对不保存任务正文或原始幂等键，私有提议正文仍遵守已有期限与权限。

## 桌面边界

新增五个精确 IPC：`organization-project:risk-evaluate`、`risk-review`、`risk-reviews`、`risk-feedback`、`risk-lineage`，由 `electronAPI.organizationProject` 暴露。组织通道总数为 33；生成清单为 1292 个精确通道，156 个未注册 renderer 通道明确拒绝。

反馈按“事务校验输入/当前授权 → 原生确认 → 固定身份及授权快照重验 → 事务保存”执行。绑定真实认证 generation、数据库、窗口、当前 frame 和导航代；换身份、同 DID 重新认证、导航恢复、换 frame 或撤权均拒绝写入。非法任务、原因、字节限额和参数在打开确认前拒绝。

独立组织风险 Vue 组件不嵌入个人目标组件，只保留 `{review,evaluation}` 显示事实。身份、项目、组织或权限变化清理事实和反馈草稿并丢弃迟到响应；权威错误通知父工作区清理任务/提议内容。风险选择变化使尚未返回的旧预览失效。未知反馈状态按身份/项目/组织/检查隔离，不传递给另一成员。
