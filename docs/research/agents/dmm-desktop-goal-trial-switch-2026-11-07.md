# 桌面持续目标试点开关

本页记录 DMM-10 默认关闭工作的工程边界；不代表生产灰度、安装客户端迁移或数据库降级已验收。完整原计划仍以[分析与实施计划](./chainlesschain-dots-muse-mods-analysis-2026-10-06.md)为准。

桌面主进程仅在启动环境中 `CHAINLESSCHAIN_PROJECT_GOALS=1` 时开放个人与组织持续目标。未设置、`0`、`true` 和其他值均关闭。`NODE_ENV=test`、Graph 的 `legacy/canonical` 选择、插件声明、renderer 参数和既有目标记录都不能代替这项显式配置。环境在主进程加载策略时固定，运行中修改环境不会启用功能。

试点时，在启动桌面进程前显式配置 `CHAINLESSCHAIN_PROJECT_GOALS=1`。关闭时移除这项启动配置并正常退出、重新启动应用。重新启用仍须显式配置并重启；既有巡检配置和有效授权保留，可能继续运行，因此重新启用前须核对原有目标与授权。这不是清除授权或数据库降级操作。

主进程另有不暴露给 renderer 的 `disableFeature()` 生命周期方法。它先同步拒绝新目标请求与在途上下文，随后等待个人/组织监控宿主和 CLI/IDE 连接退出。失败会报告 `GOAL_FEATURE_DRAIN_FAILED`，开关保持关闭。正在等待用户操作的连接授权框会延后退出完成；确认返回后不能导出可用连接。其他目标原生确认返回时也会重新检查策略，不能继续业务写入；此开关不声明能够自动关闭操作系统模态窗口。

关闭状态的行为：

- 不初始化目标 scheduler、Graph 或它们的私有存储目录。个人与组织目标 IPC 在访问数据库前拒绝请求，返回 `GOAL_FEATURE_DISABLED`。
- 组织的通用提议、审批和执行入口遇到目标关联请求时也检查策略，不能绕过目标入口的关闭状态。普通任务、组织任务审批和风险入口继续使用原有权限规则。
- 已打开的临时连接失效，并等待 loopback 服务关闭。已有连接文件可能保留，但凭据不能继续使用。
- 界面读取主进程状态后才展示目标控件。直接调用 IPC 仍由主进程独立拒绝。
- 目标、任务、回执和记忆不被删除。关闭期间目标详情读取接口也关闭；经过显式重新启用与当前身份授权后可再次读取历史。既有通知继续经过原有来源授权检查，不因开关放宽权限。

验证使用明确启用的测试配置和隔离原生 profile，不把测试环境本身作为启用条件。`project-goal-native-journey.mjs --default-off` 不设置该环境变量：在实际 Vue/原生对话框完成普通任务取消与创建后，检查目标控件隐藏、真实公开 IPC 拒绝，并跨真实 70 秒确认没有目标表或目标调度目录。常规原生目标、记忆/通知、风险创建和移交旅程均显式启用。

本批不证明安装包升级/降级、完整数据库迁移回退、其他系统 GUI、生产样本效果或原生模态框中的真实并发撤权已全部完成。发布版本与 npm OIDC 门禁未改变。
