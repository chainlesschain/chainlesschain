入口是桌面个人目标动作区的 **本机模型起草（逐次原生授权）**。先配置受治理的本机 Ollama，使用 `127.0.0.1` 或 `[::1]` 明确端点；目标允许对应动作并存在当前风险来源。选择说明/创建、任务类型和是否使用记忆。每次 native consent 显示模型、地址、完整拟发送资料和治理证据保留说明；安装组合插件或巡检调度不启动模型调用。CLI/IDE 现有入口仍使用用户正文。

`project-delivery-model-drafts` 是独立原生身份。请求日记绑定 actor/完整目标引用/原请求、来源、Memory token、模型、批准/撤权、治理 evidence 引用与输出摘要，不保存 prompt、输出正文或凭据。正文只保存到原生待审队列；pending 和日记成功状态同事务提交。同目标的旧请求 ID 不因目标修订而获得第二次 dispatch，已有请求始终只查；失败/unknown/not-found 不自动重发。单目标最多 100 个请求身份，撤销保留历史。

`revalidateOutputInTransaction` 复用原 Kernel 精确读取/授权，在模型输出及 native action 事务内验证；无事务调用拒绝。当前可读关联记忆最多 20 条，输入至多 16 KiB，不默默截断超限内容。模型响应只可提供 title/description，不能替换 type/taskType、风险来源或审批。30 秒总期限覆盖异步治理准备；响应有界、严格 UTF-8、非流式、无工具，端点不经 mutable Axios、代理、重定向、重试或 fallback。复用的本机适配器仍经过既有 signed ingress/projector，无原始调用旁路。

业务写入仍须第二次原生预览/逐次确认。记忆撤权/修正/删除/到期或来源变化阻止未确认草稿、预览和动作；已完成业务回执保留。UI 使用原生最早输出到期时间清除可见正文/标题并失效父预览。撤权不撤回已发送资料；治理系统已保存的输入/响应保留原有生命周期，未实现或宣称物理擦除全部副本。

有限 token/费用预算当前不能得到可信的预留上界，因此在调用前拒绝；运行次数与时间预算继续约束。socket 前同事务记录 usage unknown，响应后记录可用的实际计数和已知下界。费用缺失保留 null；本机端点不证明费用为零。超时或退出不释放未知消费，也不靠重发“修复”账本。原生对话框拒绝会留下拒绝身份且不触发模型或 usage 预留。
