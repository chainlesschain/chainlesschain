# OpenAI 剩余五项失败：根因与工程修复

本轮修复了两处产品逻辑缺口，并补齐五项失败涉及的测试断言和边界控制。最终定向工程回归 **28/28** 通过；原验收器的 **5/5** 个行为变异全部被拒绝，另一个“撤销完整历史分叉修复”的回归模拟也被拒绝。

这是人工辅助的工程修复，不是重新生成模型候选，也不是新的五项模型验收。没有新增模型请求或付费调用。原始六项复测结果仍为 **1/6**，跨版本累计仍为 **40/45**；[原始报告](../retest-six-99b93fc209/REPORT.md)、候选和成绩保持不变。

## 五项原因

| 失败项                    | 原因                                                                                                                                                             | 本轮处理                                                                                                                                                                              |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verify-08`               | 完整历史分叉复用了要求严格缩短上下文的 rewind 逻辑，导致合法来源 capability 无法生成。原候选还错误要求 UI 展示历史包含内部 system lineage notice。               | 完整历史分叉独立验证内容指纹、head、消息计数和来源 ordinal；保留错误父会话、改写正文、伪造和过期 capability 的拒绝控制。测试分别检查持久化内部提示与展示消息。                        |
| `verify-13`               | 候选自身通过，但没覆盖同句柄、同内容、同大小而仅 mtime/ctime 变化，以及超过像素上限的情况；因此未识别验收器注入的错误。                                          | 图像生产 guard 原本正确，不修改生产实现。工程测试增加独立 mtime/ctime 控制、像素限制边界和正向对照；文件替换 fixture 兼容 Windows。                                                   |
| `verify-19`               | 候选覆盖了用户 cancel/decline，但没有触发拥有者 turn abort 后清理真实 pending approval 的路径，漏掉取消时错误批准的变异。                                        | 审批生产实现原本正确。工程测试使用真实输入流和待审批请求，在请求发出后取消拥有者，再发送绑定正确的迟到 accept；验证返回 false 且工具执行数为 0。                                      |
| `verify-36`               | 后台任务恢复 argv 时丢失独立插件/MCP 自动连接限制；非法 MCP tri-state、列表及布尔值会被宽松转换；非法权限/沙箱/预算参数在 capture 阶段先回落默认，绕过后续验证。 | 保留独立限制并注册真实 `--no-plugins` / `--no-mcp-auto-connect` flags；在加载定制前应用限制。严格拒绝非法策略字段、参数缺值和预算格式，保留显式空工具白名单与显式 MCP 配置/桥接选择。 |
| `first-run-darwin-vscode` | 与 verify-08 共用完整历史分叉缺口，同时需要校正内部 lineage notice 的断言位置。                                                                                  | 使用同一产品修复；独立首轮工程测试继续覆盖真实历史导入，以及错误来源、摘要和截断的拒绝。                                                                                              |

五项失败并非五个互相独立的产品 bug。历史分叉影响两项；图像和取消审批两项属于候选测试覆盖不足。`verify-36` 在原冻结项目的候选有四条失败；适配当前源码后仍可复现三条失败，说明当前代码也存在产品缺口。本轮修复当前实现，没有改写冻结项目或历史候选。
