## 执行范围与固定预算

Windows 11 24H2 x64、Ubuntu 24.04 x64、macOS 15 arm64，分别使用 CLI、VS Code 1.132.0、IntelliJ IDEA 2025.2，共 9 层。固定 Node 22.12.0。36 个任务按清单顺序循环分配，每层 4 个任务，Volcengine 与 OpenAI 各 2 个。首次安装每层另有 1 个 Volcengine 样本；**这不是 OpenAI 的首次授权验收，也不是每个任务的全矩阵重复**。provider 固定为清单列出的精确模型，不允许静默 fallback、改网关或替换为本地模型。

每个项目任务总费用上限 2 USD、20 分钟；首次旅程 3 USD、30 分钟。上限覆盖首次尝试及最多一次补救重试，总预算 99 USD。不得以重试获得新的预算。费用不能实时可靠计量时，必须先落实 provider 硬额度或停止，不把 unknown 当作零。凭据仅使用隔离环境的受控注入，不写入产物。

观察窗口固定为 **2026-10-05 00:00 UTC 至 2026-10-12 00:00 UTC**。维护工时预算 16 小时，记录安装、修复、支持、兼容、发布、测试基础设施；construction 单列，不计持续维护成本。各入口保留启动后的 8h/24h 观察回执及实际覆盖时长，不允许通过等待时钟推断稳定。缺账号、未发布、机器不可用或窗口不足时保留缺失样本；需要改变窗口/版本/身份时，在任何新执行前创建带变更理由的新计划版本和指纹，不能改写此计划或剔除失败分母。

## 干净公开安装与实际宿主

每个首次旅程使用全新用户目录、配置和 IDE profile，从正式公开 npm/IDE 分发地址取得精确版本。记录下载 URL、版本、SHA-256、安装日志、运行时与对应源码提交；不得使用开发 VSIX、源码软链接、已配置用户目录或旧缓存充当干净安装。CLI 先于 IDE 安装，绑定其正式发布来源。缺少候选对应公开产物时安装阶段保持未运行。

首次运行按现有五阶段 `install → configure → authenticate → tool → artifact` 保存回执，失败阶段及依赖它的未运行阶段分别注明失败/跳过原因。9 个首次旅程在独立 checkout 运行前 9 项任务，不能把任务组的历史结果复制过来。

每个任务从同一固定项目快照新建隔离 checkout，依赖只按 lockfile 安装。允许的改动是任务交付测试/文档及反例必要的最小源码修复；保存完整 diff，额外改动单列。先执行原有相关测试建立基线；环境失败不能算 Agent 修复失败或成功，须如实归因。禁止修改计划和验收器、删断言、跳过失败测试或提交无实质断言的空测试。

CLI 保存真实执行终态、tool 记录和独立验收输出。VS Code / JetBrains 必须在实际安装宿主提交提示词，记录后台 tab 切回、最终结果、重载后结果与交付文件的一致性；题目涉及草稿、附件或模式时再保存对应实际操作回执。CLI headless 执行不能冒充 IDE 任务成功，宿主 fixture 也不能冒充真实 provider。

## 验收与既有工具的接入边界

每项验收检查 `tasks.json` 的具体正反条件、补丁及实际命令输出。独立验收者在执行前锁定新增测试路径及确定性反例，执行相关旧回归与新增测试，并用受控错误行为验证断言确实会失败；不能由产生补丁的同一模型口头评分。文档题检查所有命令与当前脚本参数一致，fingerprint 成功、无 observations 返回 2，且不得暗示改善或生产通过。当前只冻结这些验收要求，未生成通过回执。

**现有 `cc eval --suite` 仅支持 builtin，不能直接运行此任务目录。** 此目录不是声称已经接入的自定义 suite，也没有新增 runner。2026-10-05 已补[只读采集准入校验](./COLLECTION_README.md)，核对预先锁定的计划/review、文件字节和导入的既有记录，不执行任务或生成观察数据。后续实际采集可复用 `runEvalSuite`/`createEvalHistoryRecord` 等现有接口，但须先提供并审阅实际项目 setup/check 及 IDE 终态采集接线。没有真实执行协议回执时，不能手工伪造 `terminalVerified`，outcome 继续缺失。该执行接线属于真实验收准备，尚未完成；不影响任务与预算已经冻结。

比较上下文包含任务目录摘要和目标环境/权限/推理摘要；执行端必须保留原始请求配置及实际身份回执，验证与声明相符。Node/OS/模型身份或版本不符时拒绝合并统计；仅有同名模型不证明服务端 checkpoint。使用精确被测发布源码 SHA 作为 Eval label，项目 checkout 另按本目录固定 SHA 保留。不得使用文档提交 SHA 冒充产品源码 SHA。

## 结果口径

36 个任务固定分母，9 个首次旅程另报。缺失样本保留在分母并显示 `missing`；未开始不是已观察失败。现有工具无证据时可能输出数值 0 的覆盖保守成功率，报告必须同时显示 observed=0，不能描述成“执行了 36 题、成功率 0%”。不合并不同 stratum 宣称模型优劣；当前一次采样不用于显著性结论。

原始成功要求产物验收通过、终态可验证、身份匹配、预算内且无人工补救。保留首次尝试结果、自动重试数、人工修复数及补救后的最终验收结果；有人工修复即不计原始成功。另在原始回执列出 strict first-attempt success（零重试），不要将既有 outcome 允许的自动重试成功叫作首轮成功。恢复结果未知时不重跑副作用。

费用覆盖失败、重试和补救；缺账单/usage 的费用为 null/unknown，估算和实际账单分开。只有完整费用才能报告每成功任务成本。缺维护记录时 totalHours/per100Attempts 保持 null。失败原因沿用现有十类；未证实原因保留 unknown。补救成功不是原始成功，计划冻结不是 `BASELINE_RECORDED`，完整基线也不是改善 PASS。
