# 后续火山测试预算与暂不重测规则

用户要求后续火山token预算为Sol的2倍、内部摘要也为2倍，并要求已测试的暂时不重测。[执行策略及用户原文](../execution-policy.json)已记录，新的失败补测调度入口在暂停状态下拒绝执行。当前已启动的两轮及既有候选独立验收继续，不为修改预算重跑样本。

| 限制                   |               Sol配置基准 | 后续火山新策略 |
| ---------------------- | ------------------------: | -------------: |
| 单次任务输出           |                      8192 |          16384 |
| 内部摘要输出           |                      2048 |           4096 |
| 每项累计输出额度       |         196608（24×8192） |         393216 |
| 每项累计输入加输出额度 | 983040（24×(32768+8192)） |        1966080 |
| 模型轮次 / 物理请求    |                   20 / 24 |        40 / 48 |

累计基准由Sol配置额度推导，不是历史实际消耗或账户账单。请求前按JSON字节数加协议framing保守预留输入额度，并按剩余额度缩小本次输出；返回完整用量后结算，内部摘要、缓存输入也计入累计。用量未知保留预留额度并停止后续请求；提供方报告的用量超过预留边界同样拒绝继续。没有自动增加预算或创建新尝试。

这样不会因请求数和单次输出都翻倍而把累计输出放宽到四倍。旧完整轮仍保留各自源提交、策略摘要和原始回执，新策略尚未用于付费模型测试。

离线验证：30个工作流契约文件，203项通过，零失败/跳过；包括真实loopback请求、累计额度耗尽前拦截、未知用量保留及暂停调度。源码出网清单88个候选，零未审阅/失效条目、零解析错误。完整[TAP记录](./contracts.tap.txt)和[源文件摘要、配置及验证结果](./validation.json)保留；这些检查不计为45项模型任务通过。
