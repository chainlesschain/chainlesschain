本次按用户指定的 [36+9 任务清单](../../verify01-36-plus-9-task-list.md)重新合并历史成功，**火山历史自动交付累计为 34/45：任务 27/36、首次安装 7/9，75.6%**。原先将 `.139` 内部累计 17/45 当作火山全部历史累计的说明不完整，现予更正。

合并依据是历史 `.106` 及此前的 32 项已接受索引，加 `.128` 的 `verify-06` 和 `first-run-linux-cli` 两项候选合格记录；`.131`、`.132` 无新增。`.139` 的 17 个通过 ID 全部已包含在这 34 项内，因此全历史净新增 0。最新补测通过的 01/32 不可重复增加成 36/45。原始单轮 15/45、补测 2/12 都保留，[只含 .139 的 17/45](../provider-output/completion-status.json)已明确限定范围。

[机器可核对累计账本](cumulative-status.json)列出全部 45 个 ID、成功依据、来源摘要、11 个未合格 ID，以及“历史成功但本次未复现”的分层。此前通过不会因后续失败从累计中移除，后续失败也不会被删除。

34/45 保持既有“历史自动交付”标准；其中 `.128` 的 `verify-06` 候选验收通过，但生成/端到端未通过。该边界已由原始 gzip 摘要及 SHA-256 再核实并单列，不把它升级成严格端到端通过。原 32 项采用既有已接受索引；本次没有重新验证其已不在本工作树的 tar 归档字节。正式冻结 `NOT_RUN` 记录不改写。

## 已找到的具体失败

- **导入路径错误**：`.139` 补测的 `verify-08`、`verify-36` 位于 `packages/cli/__tests__/`，却导入 `../../src/lib/...`，导致候选收集不到任何测试。原有基线分别 58/58、7/7 通过，错误出现在候选导入阶段。
- **调用签名错误**：`verify-11` 把对象作为 `journal.settle()` 的首参数；冻结源码签名是 `settle(requestId, binding, outcome = {})`。实际得到 `Unknown background interaction request: [object Object]`；原基线 16/16 通过，候选 3/6 失败。这是可以确认的候选生成错误。
- **只检出部分缺陷**：`verify-04` 检出短/长请求桶合并，却漏检从阈值计算中去掉缓存 token 的反例；`verify-07` 检出边界重复，却漏检首行被跳过的反例。两项都不是完全没检出任何变异，也不是因为一个变异被检出就应全部通过。回执的后一个变异运行仍全部通过，原验收拒绝有依据。
- **网络发送前失败**：`verify-14`、`verify-33` 的 TCP/TLS 连接报 `ETIMEDOUT` / `ENETUNREACH`，HTTP 尚未发送。33 此前 5 次请求已完成，不能当作零模型调用重新包装；这些是基础设施问题，不归因为模型能力。
- **循环停滞**：首次 macOS CLI 重复读取已交付区间，16 次请求后被六批无进展保护终止。下一阶段需核对压缩后来源信息是否仍可供模型使用，再判断是恢复策略还是模型使用工具的原因。

以上依据均来自[未修改的独立验收回执](../provider-output/final-ba504a7869/receipts/)和[网络原始回执](../provider-output/network-receipts/)。`verify-15` 的候选断言与实际错误不符、首次 macOS VS Code 的断言失败也已保留；未把这些未经逐项源码确认的原因全部指向模型。

## 为什么不能直接下“模型整体变差”的结论

1. 之前拿 Sol 的跨版本累计和火山 `.139` 局部新记录比较，遗漏火山历史 34 项，放大了差距。沿用旧冻结项目的累计口径，应先列火山 **34/45**、Sol 历史 **41/45**，而非 17 对 41。Sol 后续修订项目上的失败队列已清空，仍不是 `.139` 同版本全量 45/45。
2. 历史 `.106` 也关闭 thinking，并有相同的 20 轮/24 请求/8192 输出限制，所以不能说 thinking 是本次才被关闭；已核对[旧生成摘要及配置边界](comparison-boundaries.json)。`.128` 起显式增加独立 change review，仍共用原轮次预算，和早期交付条件不同。运行时版本、协议、上下文处理与重复次数也不同。
3. `.139` 新候选中的错误确实存在，统计更正不会抹掉它们。导入路径、API 参数及行为覆盖错误说明任务层面的生成/复核存在问题；但网络、已修复的测试代理上限、不同项目修订及单轮与累计差异，不能一起算成模型能力差距。
