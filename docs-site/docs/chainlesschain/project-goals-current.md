# 项目目标、持续风险巡检与独立验收

> 2026-10-08；主线源码核对至 `381f8018ef`。产品 `v5.0.3.139@e812a89952` 已包含个人目标、巡检、动作与独立验收面板；记忆面板与站内通知需后续主线。公开 CLI `0.166.92` 的 `cc goal` 是独立文件目标系统。

## 概述

个人项目可以保存长期目标、明确开启风险巡检、查看建议，经当前预览与原生确认修改任务，并独立核验业务条件后完成目标。创建目标不会自动执行；巡检成功、模型自评或进度 100 都不等于业务验收完成。

本指南根据 `docs/research/agents` 的 Dots/Muse/Mods 实施进度、源码面板及验证记录补齐。授权记忆面板、站内持久通知与目标深链接已接入主线；自动模型记忆注入、场景包和真实业务效果仍待验收。

## 核心特性

- 目标有版本、个人项目归属和共享预算；身份或版本改变使旧证据失效。
- 显式巡检检查逾期任务与未完成直接依赖，保存原生风险证据。
- 建议经过持久准备、当前预览、原生确认和 ActionRun 回执。
- 独立验收重新读取任务、选定风险、目标动作及人工确认。
- 停止本次、暂停目标、结束跟进和验收完成分别显示真实状态。

## 系统架构

桌面主进程从可信登录会话解析 DID，检查实际个人项目归属。项目目标、风险、意图和验收放在原生项目 SQLite；后台调度使用独立私有账本。主进程退出或连接切换会排空旧宿主。两库间结算投影可恢复，但没有共同原子事务。

风险检查、原生动作及验收共用每目标次数/时间预算，同时受 principal 全局额度限制。当前巡检是规则检查，没有模型调用；未知动作耗时或将来的模型费用不写成零。

## 使用示例

1. 以 PIN 或密码登录，打开有实际归属权限的个人项目详情，点击“项目任务”，在抽屉中找到直接嵌入的“项目目标与巡检”。
2. 填写目标和“最多检查次数”，点击“保存目标”。此时只保存意图。
3. 选择检查间隔，点击“开启巡检”；需要一次检查时点击“立即检查”。预算、期限或授权阻塞按卡片提示处理。
4. 在目标动作面板设置允许范围，选择建议并准备当前预览，再打开原生确认。核对对象和版本后执行，查看原始回执；创建或改描述不自动修改依赖与期限。
5. 在“独立验收”选择明确条件，点击“保存这些验收条件并更新目标版本”。如含人工条件，点击“打开原生人工验收确认”。
6. 点击“检查验收条件”查看逐项结果。业务条件满足后点击“重新检查并完成目标”；它会再次读取当前业务事实。只有可授权读取的当前完成证明才显示已验收。

| 控制入口           | 效果                                                           |
| ------------------ | -------------------------------------------------------------- |
| 停止本次检查       | 停止指定在途检查；后续巡检配置保留；等宿主结算才确认停止       |
| 暂停目标           | 禁止未来派发；在途执行排空后显示已暂停                         |
| 重新启用目标       | 恢复 active；之后需另点“开启巡检”                              |
| 结束持续跟进       | 目标置为 abandoned，关闭未来巡检；在途执行完成停止后显示已结束 |
| 重新检查并完成目标 | 独立验收当前事实并保存完成证明；关闭未来巡检                   |

### 当前验收条件

“项目非空且所有任务已完成”要求全部当前任务为 completed，空项目或取消任务不能满足。“选定风险已消除”只检查明确选择的逾期/依赖信号。“目标动作均已解决”要求没有 draft/prepared/running 意图。人工条件由当前版本的原生确认记录证明，不能用聊天文字替代。

### CLI 目标的独立用法

```bash
cc goal set "整理项目交付资料" --json
cc goal list --json
cc agent --goal <id>
cc agent --goal <id> --goal-assess
```

CLI 目标继续保存为 `<home>/goals/<id>.json`，可跨会话绑定；`--goal-assess` 会额外调用一次模型，产生相应用量/费用并保存可选自评和进度记录。`cc goal close` 是人工关闭，不生成桌面业务完成证明。当前没有用户可用的 CLI→个人项目显式导入流程。

## 目标记忆与站内通知（主线源码）

在目标卡片“目标记忆”选择用户明确事实、Agent 推断或执行备注，输入内容并显式保存。可查看来源、范围、版本和到期，修正、撤销本目标使用权或两步删除；结果不确定时查询原操作并恢复，目标修订后的未关联记忆可显式丢弃。读取失败、到期和身份变化会清除旧正文。partial 表示清理仍待恢复，purged 不证明 WAL、备份或已导出文件被物理擦除。当前记忆没有自动注入模型回答。

在目标通知策略中明确选择静默方式与免打扰时区/窗口，并保存当前版本。桌面通知中心展示授权提示，点击后重验权限并定位指定目标；最多显示最近 50 条。已读风险不会因重复检查重新变为未读。通知仅是历史检查提示，当前风险需重新检查；不会自动发送 OS 通知。

## 配置参考

界面检查间隔为 1 分钟、15 分钟、1 小时、1 天；服务合同允许 1 分钟至 7 天，离线周期合并一次。目标界面次数预算为 1–1000；检查、动作和验收累计共享额度。保存验收条件会增加版本，需重新确认人工条件。

每目标最多保留 1000 次有效检查/手动意图、500 条建议及 500 条动作意图；状态显示最新 20 条检查。本页描述个人项目；组织目标另用独立授权、共享预算和多级审批，见[组织项目指南](./organization-project-current)。

## 性能指标

单次扫描与执行上限 50 项；单次检查最多新增 100 条建议，达到容量会显示省略量并保留完整检查。记录整体上限 64 KiB。当前只有有界实现和本地控制证据，没有真实业务样本的时延、费用或长期 SLO 承诺。

## 测试覆盖

研究记录的验收批 30 个不重叠文件、545 项通过且无失败/跳过：CLI 292、Desktop 172、Renderer 79、隔离打包 2。包含 13 项真实 Node 进程恢复。Electron 窗口和确认框在宿主测试中为替身，真实 GUI 及业务效果尚未验收；不同历史批次不累计。

## 安全考虑

默认加载 DID 不等于真实登录。锁定、退出、UKey 拔出或驱动/身份切换会撤权；软件密码模式不要求 UKey。原生确认返回后再次验证窗口/frame、身份、数据库连接、归属和版本，导航或修订后的旧确认失效。目标允许动作列表不能代替业务授权。

结果未知时沿原 requestId/intentId/ActionRun 核对。未知动作不自动重做，已经消费的预算不因停止而退回。旧验收证明不会授权新目标版本。

## 故障排查

| 现象               | 处理                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------ |
| 找不到目标面板     | 确认使用 .139 或本页源码宿主，在个人项目详情点击“项目任务”，查看抽屉中嵌入的目标面板 |
| 提示未登录或无权限 | 完成当前身份真实登录并检查项目归属；切换身份后重新读取                               |
| 授权策略已更新     | 刷新当前目标，按最新策略重新开启巡检                                                 |
| 检查/确认超时      | 使用“重试本次检查”“重试本次验收检查”或“核对本次完成结果”，保留原请求身份             |
| 正在暂停/停止/结束 | 等待在途执行真实结算，查看回执，不以按钮点击推断终态                                 |
| 预算耗尽或到期     | 检查累计检查、动作、验收及预留额度，按允许的目标修订流程调整                         |
| 验收失败           | 查看逐项结果和当前业务来源；先解决未完成任务、选定风险或未决动作，再重新检查         |
