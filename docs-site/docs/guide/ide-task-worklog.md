# IDE 任务记录与新会话接力

从 CLI `0.166.59`、VS Code `0.37.105` 和 JetBrains `0.4.126` 开始，长任务可以把过程保存为有界 Markdown，并在独立新会话中继续。CLI `0.166.58` 及更早版本不支持此功能。

## 安装与兼容性

先升级 CLI：

```bash
npm install --global chainlesschain@0.166.59 --registry https://registry.npmjs.org
cc --version
```

- VSCodium、Cursor 等 Open VSX 客户端：安装 `0.37.105`。
- 官方 VS Code：从 [Open VSX](https://open-vsx.org/extension/chainlesschain/chainlesschain-ide) 下载 `0.37.105` VSIX，再运行 **Extensions: Install from VSIX...**。
- JetBrains 2024.2+：在 Marketplace 安装 `0.4.126`。

CLI 与插件应成对升级。旧插件没有接力入口；旧 CLI 会被新版插件明确识别为不支持，不会静默迁移。

## 它解决什么问题

长任务经过上下文压缩、暂停或重启后，助手可能忘记已检查的文件、失败的测试和下一步。启用本功能的 IDE 会话会自动保存任务记录；需要更换会话时，新会话只读取经过校验的工作记录，不复制完整旧对话。

记录由真实运行事件生成，不需要提醒模型写总结，也不额外调用模型。记录有长度上限，因此不能替代完整聊天、源文件或测试日志；恢复时仍须核对最新文件。

## 开始独立新任务

在 VS Code 对话标签栏点击 `+`，或运行“新建对话”命令；在 JetBrains 点击 `+ New chat`。每个标签页使用独立会话和上下文，不自动带入旧任务，也不会停止其他独立任务。

## 带历史继续当前任务

1. 在旧任务中，VS Code 点击标签栏 `↗`，或从命令面板运行 **Continue in New Conversation with Task Notes**；JetBrains 点击 **Continue in new chat**。
2. 等待当前工具结束并保存记录。若正在等待权限确认，先处理确认卡。保存成功前不会关闭旧任务或创建接力会话。
3. 新对话会预填继续提示词。可以直接发送，也可以先改成更具体的要求。

新对话使用新的会话 ID，不继承旧聊天、临时授权或执行中的工具调用。历史加载失败时不会调用模型，旧会话和原记录都会保留。“新会话”指 IDE 内的新标签页，不会启动新的 IDE 进程。

## 查看任务记录

记录位于项目目录：

```text
.chainlesschain/sessions/<session-id>/WORKLOG.md
```

它包含目标、最近补充要求、已读取文件、版本证据、修改、工具结果、失败尝试、最近计划以及压缩/暂停边界。`turn-ended` 只表示一轮结束，不代表任务已完成；已启动但尚无结果的工具会标为结果不明确。

Markdown 最大 32 KiB，旧明细会裁剪并保留裁剪计数。文件可能在记录生成后变化，因此接力会话在修改前会重新核实相关片段。

## 权威状态与安全边界

Context/Memory Kernel `0.1.4` 的会话检查点是权威状态，Markdown 只是便于查看和交接的投影。Markdown 丢失或被改动时，可以从检查点重建；手工编辑 Markdown 不会授予权限、覆盖权威状态或自动写入长期记忆。

新会话把历史视为有界、低信任资料，用户最新要求始终优先。常见凭据会被遮盖，但工作记录仍可能包含项目代码和错误信息，分享前应检查。shadow 模式只观察，不写任务检查点。

## 常见问题

| 情况 | 处理方式 |
| --- | --- |
| 提示需要更新 CLI | 升级 CLI 和插件，发送一条消息完成会话初始化后再接力。 |
| 等待保存超过一分钟 | 旧对话会保留；检查运行中的工具或待处理确认卡，处理后重试。 |
| 无法保存记录 | 检查项目目录权限、磁盘空间和 Context/Memory 模式。保存失败不会迁移。 |
| 历史加载失败 | 新会话不会执行任务；确认工作区相同且原会话日志仍存在。 |
| 手动删除 Markdown | 原会话检查点仍存在时，交接可重新生成 Markdown。 |
| 文件已被他人修改 | 以当前文件为准，重新核对历史结论后再修改。 |

## 当前范围

当前只支持显式点击接力，不会根据 token 阈值自动创建新会话，也不会从普通消息推断任务切换。该限制用于控制交接次数，避免同一失败循环不断创建会话。

设计和协议边界见[IDE 任务过程持久化与新会话交接方案](/design/ide-task-worklog-handoff)，完整 IDE 功能见[IDE 插件使用指南](/chainlesschain/ide-plugin)。
